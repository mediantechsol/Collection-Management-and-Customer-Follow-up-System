# 🧠 ذاكرة المشروع الشاملة — نظام إدارة التحصيل ومتابعة العملاء

> **الغرض**: هذا الملف هو المرجع الوحيد والشامل لأي وكيل ذكاء اصطناعي يتابع التطوير.
> اقرأه كاملاً قبل أي تعديل. لا تحتاج لشرح إضافي من المستخدم.

---

## 1. 🎯 ماهية المشروع

نظام مركزي لإدارة تحصيل المديونيات ومتابعة العملاء، مبني لـ **مكتب الدكتور أيمن لخدمات الدواجن** (اليمن).
يحلّ محل ملفات Excel يدوية موزّعة على 5 مسؤولي تحصيل، بقاعدة بيانات واحدة وصلاحيات مفروضة على مستوى قاعدة البيانات.

- **العميل**: مكتب الدكتور أيمن (يمن)
- **اللغة**: عربية بالكامل (RTL)
- **المستخدمون**: ~5 مسؤولي تحصيل + محاسب + مدير النظام
- **البيانات**: ~360 عميل، 3 عملات (يمني/دولار/سعودي)

## 2. 🏗️ البنية التقنية (Tech Stack)

| الطبقة | التقنية |
|---|---|
| **الواجهة** | React 18 + TypeScript + Vite 5 + Tailwind CSS 3 |
| **إدارة البيانات** | TanStack Query v5 (react-query) |
| **التنقل** | React Router v6 |
| **قاعدة البيانات** | PostgreSQL 15+ عبر Supabase |
| **المصادقة** | Supabase Auth (بريد داخلي `username@dr-ayman.local`) |
| **الأمان** | Row Level Security (RLS) على كل الجداول |
| **Edge Functions** | Deno (admin-users فقط) |
| **استيراد Excel** | مكتبة `xlsx` (محمّلة بـ lazy loading) |
| **الاختبارات** | Vitest (49 اختبار) + فحوصات RLS يدوية |
| **الجدولة** | pg_cron لتوليد التنبيهات اليومية |

### مسار الـ Alias
```typescript
// vite.config.ts

```

### متغيرات البيئة المطلوبة (`app/.env.local`)
```

VITE_SUPABASE_ANON_KEY=eyJ...
VITE_INTERNAL_EMAIL_DOMAIN=dr-ayman.local
```

> ⚠️ **لا يوجد `service_role key` في كود الواجهة إطلاقاً**. مكانه الوحيد: أسرار Edge Functions.

## 5. 🔐 نموذج الصلاحيات (الأهم في النظام)

### الأدوار الأربعة

| الدور | الصلاحية |
|---|---|
| `مدير النظام` | كل شيء — إدارة مستخدمين وإعدادات |
| `المحاسب` | عملاء + أرصدة + استيراد + اعتماد دفعات (بدون إدارة مستخدمين) |
| `مسؤول التحصيل` | عملاؤه المعيَّنون فقط + ضمن فئاته المسموحة |
| `مستخدم مخصص` | بلا صلاحيات افتراضية — يُبنى بالكامل يدوياً |

### الطبقات فوق الأدوار (لكل مستخدم)

1. **`allowed_screens`** — أي شاشات يفتحها
2. **`allowed_category_ids`** — أي فئات عملاء يراها (فارغة = كل الفئات)
3. **`screen_permissions[شاشة].actions`** — إجراءات دقيقة (create/edit/confirm...)
4. **`screen_permissions[شاشة].hidden_fields`** — أعمدة مخفية (تجميلي فقط)

### ⚠️ قواعد أمنية حرجة

- **كل قاعدة في الواجهة لها مقابل في RLS** — الواجهة تمنع عرض ما سيُرفض فقط
- **`hidden_fields` تجميلية** — RLS تعمل على الصف لا العمود
- **سجل التدقيق لا يُكتب من الواجهة** — triggers داخلية فقط
- **المستخدمون لا يُحذفون** — بل يُوقَفون + `ban_duration` على حساب auth
- **كل حساب جديد يبدأ موقوفاً بلا شاشات** — المدير يضبط الصلاحيات ثم ينشّطه

## 6. 📊 قواعد العمل (Business Logic)

### حسابات الاستحقاق
```
تاريخ الاستحقاق الجديد = due_date + grace_1 + grace_2 + grace_3
الأيام المتبقية = new_due_date − اليوم    (سالب = متأخر)
```

### حسابات المبالغ
```
إجمالي المستحق بالريال = (USD × سعر_USD) + (SAR × سعر_SAR) + YER
الحافز = المبلغ المحصَّل المعتمد × نسبة فئة العميل ÷ 100
```

### أنواع التنبيهات الستة

| النوع | المفتاح | التوليد | الوصف |
|---|---|---|---|
| قبل الاستحقاق | `before_due` | آلي | قبل الاستحقاق بـ N أيام (قابل للضبط) |
| يوم الاستحقاق | `due_today` | آلي | تاريخ الاستحقاق الجديد = اليوم |
| يسوق الآن | `shopping_now` | آلي | حالة العميل = الكلمة المفتاحية |
| وعد بالسداد | `promise_today` | آلي | نتيجة المتابعة تحتوي "وعد" وموعدها اليوم |
| بلا متابعة | `stale` | آلي | مرور N يوم بلا متابعة (قابل للضبط) |
| مراجعة المدير | `escalated` | يدوي | يرفعه مسؤول التحصيل عبر `escalate_customer()` |

> التوليد الآلي عبر `generate_daily_notifications()` — تُستدعى بـ pg_cron يومياً.
> لا يتكرر التنبيه لنفس العميل في نفس اليوم (`unique: customer_id + type + date`).

### دورة التحصيل
```
ملف الأرصدة ──► استيراد ──► زيادة الجانب الدائن ──► دفعة محصّلة (بانتظار الاعتماد)
                                                         │
تحصيل نقدي مباشر ──► إدخال يدوي ───────────────────────┤
                                                         ▼
                                                   اعتماد المحاسب
                                                         │
                                                         ▼
                                           حافز = المبلغ × نسبة الفئة
```

### استيراد الأرصدة — نقطة حرجة

- **أول استيراد**: يجب إلغاء "اشتقاق الدفعات" لأن الأرصدة تاريخية متراكمة
- **كل استيراد بعده**: يجب تفعيل "اشتقاق الدفعات" لالتقاط التحصيل الفعلي
- **Upsert**: `balances` يُحدَّث بلا تكرار (فريد: customer_id + currency)
- **balance_history**: يحفظ القيم السابقة لحساب الفرق

## 8. 🔄 نمط البيانات (Data Flow Pattern)

```
الواجهة (React)
    ↓ useXxx() hooks من queries.ts
    ↓ supabase.from('table').select/insert/update
    ↓ أو supabase.rpc('function_name', params)
    ↓
Supabase PostgREST (anon key)
    ↓ RLS policies تُصفّي البيانات حسب المستخدم
    ↓
PostgreSQL
```

### نمط TanStack Query
- **Query Keys**: معرَّفة مركزياً في `qk` object
- **Mutations**: تُبطل المفاتيح المتأثرة عبر `invalidateQueries`
- **staleTime**: 5 دقائق للإعدادات والفئات، Infinity للأدوار، افتراضي لباقي البيانات

### ⚠️ لا فلترة صلاحيات في الواجهة
RLS تُرجع أصلاً ما يحق للمستخدم رؤيته. الواجهة تعرض ما يصل فقط.

## 9. 🔑 المصادقة (Authentication)

- الموظفون **لا يملكون بريداً حقيقياً** — يدخلون باسم المستخدم فقط
- التطبيق يحوّل `username` → `username@dr-ayman.local` عبر `usernameToEmail()`
- النطاق يجب أن يتطابق في: `.env.local` + جدول `settings` + أسرار Edge Function
- إنشاء/تعديل/إيقاف الحسابات عبر Edge Function `admin-users` (تحتاج `service_role`)
- أول مدير يُنشأ يدوياً عبر `bootstrap_admin.sql`

## 14. 📐 اتفاقيات الكود (Coding Conventions)

### التسمية
- **الملفات**: PascalCase للمكونات (`CustomerModal.tsx`)، camelCase للمنطق (`queries.ts`)
- **المتغيرات والدوال**: camelCase (`calcTotalDueYER`, `useCustomers`)
- **الأنواع**: PascalCase (`CustomerOverview`, `AppUser`)
- **جداول SQL**: snake_case (`customer_categories`, `activity_logs`)
- **أعمدة SQL**: snake_case (`customer_name`, `assigned_user_id`)

### الأنماط المتبعة
- **Feature-based structure**: كل شاشة في مجلد مستقل
- **Custom hooks**: كل استعلام ملفوف في hook (`useCustomers()`, `useSettings()`)
- **Centralized query keys**: `qk` object في `queries.ts`
- **Error translation**: أخطاء Supabase تُترجم للعربية
- **Security definer RPCs**: للعمليات التي تتطلب تجاوز RLS
- **تعليقات بالعربية**: كل التعليقات والوثائق بالعربية

### ⚠️ قواعد صارمة
- لا `service_role` في الواجهة أبداً
- لا كتابة مباشرة في `activity_logs` من الواجهة
- لا تكرار لمنطق التنبيهات (التوليد في SQL فقط)
- لا `localStorage` — كل البيانات في Supabase
- لا حذف مستخدمين — إيقاف فقط
