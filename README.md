# نظام إدارة التحصيل ومتابعة العملاء

نظام مركزي لإدارة تحصيل المديونيات ومتابعة العملاء — **مكتب الدكتور أيمن لخدمات الدواجن**.
يحلّ محل ملفات Excel اليدوية الموزّعة على خمسة مسؤولي تحصيل، بقاعدة بيانات واحدة وصلاحيات
مفروضة على مستوى قاعدة البيانات لا الواجهة.

React + TypeScript + Supabase • واجهة عربية بالكامل (RTL) • تعمل على الكمبيوتر والجوال.

---

## البنية

| المسار | المحتوى |
|---|---|
| `app/` | تطبيق الواجهة (Vite + React + TS + Tailwind + TanStack Query) |
| `supabase/migrations/` | مخطط قاعدة البيانات وسياسات RLS ودوال العمليات |
| `supabase/functions/admin-users/` | Edge Function لإدارة حسابات المصادقة (المكان الوحيد لـ service_role) |
| `supabase/tests/rls_checks.sql` | اختبارات RLS ومنطق الاستيراد — **شرط قبول قبل التشغيل الفعلي** |
| `docs/` | دليل التشغيل والترحيل + توثيق بنية ملفات Excel |
| `legacy/` | النموذج الأولي المستلم (HTML + SQL) للرجوع إليه — لا يُشغَّل |

## البدء السريع

```bash
# 1) قاعدة البيانات
supabase link --project-ref <معرّف-المشروع>
supabase db push
supabase db execute --file supabase/seed.sql

# 2) الواجهة
cd app
cp .env.example .env.local     # املأ VITE_SUPABASE_URL و VITE_SUPABASE_ANON_KEY
npm install
npm run dev

# 3) التحقق
npm test                        # 49 اختباراً لمنطق العمل ومحلّلات Excel
npm run typecheck
```

التفاصيل الكاملة (إنشاء المستخدمين، ترحيل بيانات Excel، النشر) في
[`docs/SETUP.md`](docs/SETUP.md).

## الأدوار

| الدور | الصلاحية |
|---|---|
| مدير النظام | كل الشاشات والبيانات، وإدارة المستخدمين والصلاحيات |
| المحاسب | العملاء والأرصدة والاستيراد واعتماد الدفعات، دون إدارة مستخدمين |
| مسؤول التحصيل | عملاؤه المعيَّنون فقط، ضمن فئاته المسموحة |
| مستخدم مخصص | بلا صلاحيات افتراضية — يُبنى بالكامل من صلاحيات مخصّصة |

فوق الأدوار، لكل مستخدم: شاشات مسموحة، فئات عملاء مسموحة، إجراءات دقيقة لكل شاشة،
وأعمدة مخفية. كل قاعدة صلاحية في الواجهة لها مقابل في سياسات RLS.

## قواعد العمل

- **تاريخ الاستحقاق الجديد** = تاريخ الاستحقاق + مجموع المهل الثلاث.
- **الأيام المتبقية** = تاريخ الاستحقاق الجديد − اليوم (سالب = متأخر).
- **إجمالي المستحق بالريال** = دولار×سعره + سعودي×سعره + يمني.
- **الحافز** = المبلغ المحصَّل المعتمد × نسبة فئة العميل ÷ 100.
- **ستة أنواع تنبيهات**: خمسة آلية (تُولَّد يومياً عبر pg_cron) وواحد يدوي يرفعه
  مسؤول التحصيل. لا يتكرر التنبيه لنفس العميل في نفس اليوم.
- كل العتبات (3 أيام قبل الاستحقاق، 35 يوم تعثّر، 14 يوم بلا متابعة، أسعار الصرف)
  قابلة للضبط من جدول `settings` بلا تعديل كود.

## دورة التحصيل والحوافز

```
ملف الأرصدة  ──►  استيراد  ──►  زيادة الجانب الدائن  ──►  دفعة محصّلة (بانتظار الاعتماد)
                                                              │
تحصيل نقدي مباشر ──►  إدخال يدوي ─────────────────────────────┤
                                                              ▼
                                                    اعتماد المحاسب
                                                              │
                                                              ▼
                                              حافز = المبلغ × نسبة الفئة
```

## ملاحظات أمنية

- كلمات المرور تُدار حصراً في `auth.users` — لا يوجد عمود `password` في أي جدول.
- `service_role key` لا يوجد في كود الواجهة إطلاقاً؛ مكانه الوحيد أسرار Edge Functions.
- سجل التدقيق يُكتب عبر triggers داخل قاعدة البيانات، ولا يمكن للواجهة تزويره.
- إخفاء الأعمدة (`hidden_fields`) **تجميلي فقط** — RLS تعمل على الصف لا العمود.
  أي حقل حسّاس فعلاً يجب عزله في جدول منفصل بسياسة خاصة.
- المستخدمون لا يُحذفون أبداً، بل تُوقَف حساباتهم للحفاظ على سجلهم التاريخي.
