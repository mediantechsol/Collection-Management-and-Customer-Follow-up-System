# 📄 برومبت المهمة 1: قاعدة البيانات والأمان والدوال التجميعية للتقارير
## المرحلة: الأولى (Backend, Database Aggregations & Security Enforcement)
## الموديول: شاشة التقارير التحليلية (V2 - Module 1)

---

### 🎯 1. بطاقة وسياق المهمة (Context & Scope)
بناء الأساس البرمجي والأمني لخدمة شاشة التقارير التحليلية على مستوى قاعدة البيانات (PostgreSQL / Supabase)، عبر دوال تجميعية (RPCs) ومخططات حسابية سريعة تحسب مؤشرات المديونية، وأداء المحصلين، وتوزيعات العملات والحالات، مع **فرض تطبيق الصلاحيات وعزل البيانات الصارم على مستوى قاعدة البيانات**.

---

### 🔍 2. مرحلة التحليل والاستكشاف (Phase 1: Analysis & Discovery)

قبل كتابة أي كود، يجب على وكيل الذكاء الاصطناعي مراجعة وفهم ما يلي:
1. **هيكل الجداول القائمة:**
   - جدول `customers`: العملاء، الفئات `customer_category_id`، المحصل المسؤول `assigned_user_id`، وحالة النشاط `is_active`.
   - جدول `balances`: الأرصدة الحالية لكل عميل وعملة (`debit`, `credit`, `currency`).
   - جدول `collections`: الدفعات المحصلة وتواريخها `collected_date`، وحالة الاعتماد `confirmed_at`، والمحصل `user_id`، والمبلغ المعادل بالريال `amount_yer`.
   - جدول `settings`: أسعار الصرف الحالية `exchange_rate_usd` و `exchange_rate_sar` وعتبات التنبيهات.
   - جدول `users` و `roles`: الأدوار (`مدير النظام`, `المحاسب`, `مسؤول التحصيل`).
2. **شروط الأمان والصلاحيات:**
   - إذا كان المستخدم المستدعي **مدير نظام** أو **محاسب**: يتم تجميع التقارير على مستوى كامل المنشأة وكافة المحصلين.
   - إذا كان المستخدم **مسؤول تحصيل**: يتم حصر البيانات تلقائياً بـ `assigned_user_id = auth.uid()` أو `collections.user_id = auth.uid()`، مع رفض إرجاع أي مديونيات أو بيانات تخص زملاءه حتى لو تم إرسال معرّفات أخرى في الطلب.
3. **الأداء ومنع البطء:**
   - استخدام استعلامات تجميعية موحدة (Single-pass Aggregations / CTEs) لتقليل زمن الاستجابة إلى أقل من 50ms.

### 📐 3. مرحلة التصميم والمعمارية (Phase 2: Architecture & Design)

#### أ. توقيعات دوال الـ RPC المستهدفة:

1. **`get_analytics_summary_kpis`**:
   - **المدخلات:** `p_start_date date`, `p_end_date date`, `p_user_id uuid`, `p_category_id uuid`, `p_currency text`.
   - **المخرجات (JSON):**
     * `total_debt_yer`: إجمالي المديونية الكلية بالريال اليمني.
     * `total_collected_period_yer`: إجمالي المبالغ المحصلة في الفترة المحددة.
     * `active_customers_count`: عدد العملاء النشطين.
     * `overdue_customers_count`: عدد العملاء المتعثرين.
     * `settled_customers_count`: عدد العملاء المسددين.
     * `team_collection_rate`: مؤشر نسبة التحصيل العام.

2. **`get_analytics_charts_data`**:
   - **المدخلات:** فلاتر البحث المذكورة أعلاه.
   - **المخرجات (JSON):**
     * `debt_by_currency`: توزيع المبالغ حسب العملة (`YER`, `USD`, `SAR`).
     * `customers_by_status`: توزيع العملاء (`نشط`, `متعثر`, `مسدد`).
     * `collector_performance`: مصفوفة تضم كل محصل: (الاسم، المبلغ المستحق، المبلغ المحصل، نسبة الإنجاز).
     * `monthly_collection_trend`: مصفوفة الشهور (آخر 6 أو 12 شهراً) مع المبالغ المحصلة ونسب التحصيل.
     * `top_10_debtors`: قائمة أعلى 10 عملاء مديونية (الاسم، الفئة، المسؤول، المديونية بالريال).

### 💻 4. مرحلة التنفيذ البرمجي (Phase 3: Implementation)

#### أ. إنشاء ملف الترحيل بقاعدة البيانات:
`supabase/migrations/20260901000003_analytics_reports.sql`
- إضافة شاشة `'reports'` إلى جدول `public.app_screens` تلقائياً مع التسمية 'التقارير التحليلية'.
- كتابة دوال الـ RPC:
  * `public.get_analytics_summary_kpis(...)`
  * `public.get_analytics_charts_data(...)`
- ضبط الصلاحية كـ `security definer` مع التحقق الداخلي من `auth.uid()` ومطابقة دور المستخدم عبر جدول `public.users`.
- منح الصلاحية لـ `authenticated`:
  `grant execute on function public.get_analytics_summary_kpis to authenticated;`
  `grant execute on function public.get_analytics_charts_data to authenticated;`

#### ب. تحديث كود التطبيق في الفرونت إند:
1. `app/src/lib/permissions.ts`:
   - إضافة `'reports'` إلى `SCREENS` و `SCREEN_LABELS`.
   - ضبط الإجراءات التلقائية لدور المدير والمحاسب والمحصل.
2. `app/src/types/models.ts`:
   - تعريف واجهات Typescript: `AnalyticsKPIs`, `CollectorPerformanceItem`, `MonthlyTrendItem`, `ChartDataPayload`.
3. `app/src/lib/queries.ts`:
   - إضافة مفاتيح الاستعلام `qk.analytics` وخطافات React Query:
     * `useAnalyticsKPIs(filters)`
     * `useAnalyticsCharts(filters)`

### 🧪 5. مرحلة الفحص والاختبار الشامل (Phase 4: Full QA & Verification)

يجب تنفيذ جميع إجراءات الفحص التالية بدقة والتأكد من نجاحها:

1. **فحص الـ TypeScript والأنواع:**
   ```bash
   cd app && npm run typecheck
   ```
2. **فحص اختبارات الوحدة:**
   ```bash
   cd app && npm test
   ```
3. **فحص أمان وعزل الصلاحيات (Security Verification):**
   - استدعاء الدالة بحساب مسؤول تحصيل مع تمرير `p_user_id` خاص بزميل آخر: التأكد من أن الدالة تتجاهل المعامل وتعيد بيانات المستخدم الحالي فقط.
   - استدعاء الدالة بحساب مدير نظام: التأكد من ظهور كامل بيانات المنشأة وكافة المحصلين.
4. **فحص دقة الحسابات المالية:**
   - مقارنة إجمالي المديونية الناتج من الدالة مع المجموع اليدوي لأرصدة العملاء بالريال اليمني والعملات الأجنبية المحولة بأسعار الصرف في `settings`.
