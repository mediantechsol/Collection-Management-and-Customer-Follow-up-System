# 📄 برومبت المهمة 1: قاعدة البيانات وهيكل الفئات الشخصية والأمان
## المرحلة: الأولى (Database Schema, Tables, Tier Initialization & Strict RLS)
## الموديول: التصنيف الشخصي للمحصل أ/ب/ج/د (V2 - Module 4)

---

### 🎯 1. بطاقة وسياق المهمة (Context & Scope)
بناء المخطط البرمجي والأمني للفئات والتصنيفات الشخصية الخاصة بكل مسؤول تحصيل على مستوى قاعدة البيانات (PostgreSQL / Supabase)، مع عزل الخصوصية الكامل، وضمان **عدم التداخل مع فئات V1 الرسمية**، وتهيئة الفئات الأربع الافتراضية مع إسناد العملاء تلقائياً للفئة (د) كنقطة بداية.

---

### 🔍 2. مرحلة التحليل والاستكشاف (Phase 1: Analysis & Discovery)

قبل البدء في كتابة كود قاعدة البيانات، يجب التحقق من الآتي:
1. **الفرق الجوهري بين فئات V1 والتصنيف الشخصي في V2:**
   - **فئات V1 (`customer_categories`):** فئات رسمية على مستوى كامل المنشأة (مثل: "عملاء VIP", "شركات", "أفراد") تُسند للعميل في جدول `customers`، وتحدد نسبة الحافز المالي للمحصل وصلاحيات الوصول.
   - **فئات V2 (`collector_tier_settings` & `customer_personal_assignments`):** تنظيم شخصي خاص بالمسؤول فقط (أ / ب / ج / د) لترتيب أولويات عمله اليومي. لا يراها المحصلون الآخرون، ولا يراها المدير كفئة رسمية، ولا تغير أي نسبة حافز.
2. **علاقة العميل بالمحصل:**
   - جدول `customers` يحتوي على `assigned_user_id`.
   - يجب أن ترتبط التعيينات الشخصية بـ `(user_id, customer_id)`.
3. **حالة عدم التعيين الصريح (Fallback):**
   - أي عميل مسند للمحصل ولم يتم تعيينه صراحة لفئة معينة، يُعتبر تلقائياً في الفئة (د).

### 📐 3. مرحلة التصميم والمعمارية (Phase 2: Architecture & Design)

#### أ. الجداول الجديدة المطلوبة:

1. **جدول إعدادات ومسميات الفئات الشخصية لكل مستخدم (`collector_tier_settings`):**
   ```sql
   create table public.collector_tier_settings (
     id          uuid primary key default gen_random_uuid(),
     user_id     uuid not null references public.users(id) on delete cascade,
     tier_key    text not null check (tier_key in ('A', 'B', 'C', 'D')),
     tier_name   text not null,
     color       text not null default '#6B7280',
     sort_order  integer not null default 0,
     created_at  timestamptz not null default now(),
     updated_at  timestamptz not null default now(),
     unique (user_id, tier_key)
   );
   ```

2. **جدول تعيين العميل للفئة الشخصية (`customer_personal_assignments`):**
   ```sql
   create table public.customer_personal_assignments (
     id           uuid primary key default gen_random_uuid(),
     user_id      uuid not null references public.users(id) on delete cascade,
     customer_id  uuid not null references public.customers(id) on delete cascade,
     tier_key     text not null check (tier_key in ('A', 'B', 'C', 'D')),
     created_at   timestamptz not null default now(),
     updated_at   timestamptz not null default now(),
     unique (user_id, customer_id)
   );
   ```

#### ب. دوال الـ RPC والتهيئة التلقائية:
* **`get_or_init_user_tiers()`:** دالة تعيد الفئات الأربع للمستخدم الحالي، وإذا لم تكن موجودة تنشئها تلقائياً بالقيم الافتراضية:
  - `A`: اسم "فئة أ (أولوية عالية)"، لون أحمر `#EF4444`
  - `B`: اسم "فئة ب (متابعة نشطة)"، لون برتقالي `#F59E0B`
  - `C`: اسم "فئة ج (وعود ومستقر)"، لون أزرق `#3B82F6`
  - `D`: اسم "فئة د (عام / غير مصنف)"، لون رمادي `#6B7280`
* **`set_customer_personal_tier(p_customer_id uuid, p_tier_key text)`:** تعيين فئة العميل بضغطة زر مع الحفظ بـ Upsert.

#### ج. سياسات الأمان والعزل (Row-Level Security - RLS):
* تفعيل RLS على الجدولين.
* السياسة: `auth.uid() = user_id` لجميع عمليات (SELECT, INSERT, UPDATE, DELETE).
* لا يحق لأي مستخدم (حتى لو كان محصلاً آخر) قراءة أو تعديل تصنيفات شخص آخر.
